版本：0.4.0-internal.1  
日期：2026-06-12
阶段目标：先评估当前去背景质量，再决定后续优化方向。  

---

## 1. 本阶段边界

Phase 6A 只做质量评估，不直接改算法、不改参数、不改 postprocess、不改 rembg / portable Python / launcher 链路。

本报告用于回答：

```text
1. 当前去背景在不同背景下表现如何
2. 哪些场景已经适合内测使用
3. 哪些场景需要继续优化
4. 问题主要来自 Raw 自动去背景，还是 Soft 修边
5. 下一阶段应该优先优化哪一类问题
```

## 5. 人工视觉检查表

每个样本需要至少人工检查首帧、中间帧、末帧，以及运动幅度最大的几帧。

| 检查项 | 判断 |
| --- | --- |
| 主体是否完整 | 重点看头发、手指、尾巴、武器尖角、衣摆 |
| 背景是否残留 | 重点看主体周围一圈、透明洞、阴影 |
| 边缘是否发黑 | 常见于深色背景或预乘颜色污染 |
| 边缘是否发白 | 常见于白底或浅色背景 |
| 颜色是否被背景染色 | 重点看半透明区域和毛边 |
| 细节是否被抹掉 | 头发、毛绒、羽毛、烟雾、发光边缘 |
| 帧间是否闪烁 | 连续播放 Raw / Soft，观察边缘跳动 |
| 是否适合进游戏 | 放到深色、浅色、棋盘背景下分别看 |

## 6. 优化方向判断规则

后续不要一看到效果问题就直接改后处理。先按下面规则归因：

```text
Raw 已经漏掉主体：
优先考虑输入质量、模型能力、单帧预处理、素材约束。

Raw 主体完整但边缘脏：
优先考虑 Soft 修边、颜色修正、alpha 边缘处理。

Raw / Soft 单帧好，但连续播放闪：
优先考虑序列一致性、参数锁定、帧间稳定策略。

纯色背景好，复杂背景差：
优先考虑使用说明、测试样本分级、后续高级模式。

低对比背景差：
优先考虑素材前处理、模型选择、人工辅助输入，而不是只调 shrink。

半透明 / 发光差：
单独列为高级素材，不放进短期默认流程承诺。
```

## 12. 问题归因

### Raw 阶段问题

```text
主体接近背景时容易误删：01、07、08
复杂自然背景下边缘不稳：06
毛发和细碎边缘保留不足：09、11
半透明主体无法正确分离：10、12
快速运动下遮罩帧间稳定性不足：13
```

这些问题属于自动去背景遮罩质量问题。后处理不能从根本上补回已经被 Raw 阶段删掉的主体。

### Soft 阶段问题

```text
对黑边有明显帮助：02、04、05、11、14
对普通轮廓清理有效，但对误删主体无效：01、06、07、08
部分样本会出现泛白或边缘仍脏：06、09
对半透明布料和发光效果没有专项处理能力：10、12
```

Soft I 当前适合做常规边缘清理，不适合作为万能修复步骤。

## 13. 优化优先级建议

第一优先级：先限制和说明可用场景。

```text
推荐素材：绿幕、纯色背景、简单背景、主体轮廓清楚、半透明少。
谨慎素材：复杂背景、低对比、毛发、快速运动。
暂不承诺：透明布料、烟雾、玻璃、复杂发光半透明效果。
```

第二优先级：改进测试与预设。

```text
在软件或文档中增加“推荐输入素材”说明。
为低对比 / 毛发 / 半透明建立单独测试集，不要混在默认流程里判断。
继续保留 Raw / Soft 对比，帮助用户判断问题出在自动去背景还是修边。
```

第三优先级：核心能力优化方向。

```text
低对比专项：考虑输入预处理、背景相近提示、或更适合的模型/参数方案。
毛发专项：考虑更保守的 alpha 策略、边缘颜色去污染、细节保护预设。
半透明专项：不要短期承诺完全自动，先作为高级实验方向。
帧间稳定专项：考虑序列级一致性检查，而不是只看单帧效果。
```

## 14. 推广判断

当前不建议直接做大范围宣传。

更合适的节奏：

```text
先小范围内测，目标用户限定为游戏美术、TA、独立游戏开发者、外包素材处理人员。
宣传时强调“本地批量去背景 + 修边 + 透明 PNG 序列导出”，不要宣传成万能抠图工具。
展示样例优先选择 A / A- 和稳定 B 类素材。
明确提示透明布料、复杂毛发、低对比背景属于当前限制场景。
```

可用于宣传的样本：

```text
02 绿色背景
04 简单背景
14 遮挡旋转
10 发光法术可作为“半透明仍有限制”的说明样本
```

不建议作为第一批宣传样本：

```text
06 复杂室外背景
07 低明度低对比背景
08 高明度低对比背景
09 毛发测试
12 透明布料
```
