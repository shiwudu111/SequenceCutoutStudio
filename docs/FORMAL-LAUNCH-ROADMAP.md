# Sequence Cutout Studio 正式上线执行路线图

日期：2026-06-12  
目标版本：正式上线候选版  
当前基线：0.4.0-internal.1 已完成内测绿色包交付，Phase 6A 已完成第一轮去背景质量报告。

---

## 1. 总目标

把 Sequence Cutout Studio 从“内测可用工具”推进到“用户可以稳定拿来处理素材的正式产品”。

正式上线前最低标准：

```text
1. 主流程稳定：导入、切帧、去背景、修边、预览、导出不崩。
2. UI 布局固定：后续功能只扩展已有面板，不新增主流程窗口。
3. 结果可验收：用户能快速判断这一批结果是否可用。
4. 问题可定位：软件能标出疑似问题帧，而不是让用户逐帧翻。
5. 质量边界清楚：普通素材可用，困难素材有明确处理策略。
6. 发布包稳定：绿色包、launcher、portable Python 链路不破。
```

---

## 2. 防目标漂移规则

后续每个阶段开始前必须先确认：

```text
1. 本阶段唯一主目标是什么
2. 本阶段不做什么
3. 是否会影响 launcher / portable Python / rembg / postprocess 链路
4. 是否需要重新打绿色包
5. 验收命令是什么
6. 完成后是否更新 docs/ITERATION_BASELINE.md
```

后续功能扩展必须遵守：

```text
不新增主流程窗口。
不新增临时主区域。
不把 debug 信息暴露到普通用户主流程。
不恢复 .venv。
不调用 rembg.exe。
不绕开 tools/python/python.exe + tools/rembg_runner.py 链路。
不提交 portable-root / release / dist / zip。
```

## 3. Phase 6B：固定 UI 布局与功能承载边界

状态：已完成。

目标：冻结主界面结构，避免后续功能继续往界面里临时堆叠。

需求：

```text
1. 固定主界面区域：侧栏、输入区、预览区、处理参数区、导出区、质量验收区、日志/详情区。
2. 明确后续功能归属：新增功能只能进入对应面板。
3. 禁止新增主流程窗口：只允许系统文件选择器、必要确认弹窗、错误详情弹窗。
4. 高级功能默认折叠：模型选择、实验参数、缓存维护、Sprite Sheet 等不占主流程。
5. 固定常见分辨率表现：1366x768、1600x900、1920x1080。
```

执行清单：

```text
[x] 梳理当前 App.tsx 主界面结构
[x] 梳理当前 App.css 布局规则
[x] 画出正式版主界面区域定义
[x] 写 docs/UI-LAYOUT-RULES.md
[x] 在 docs/ITERATION_BASELINE.md 记录 UI 冻结原则
[x] 调整现有面板命名和区域归属
[x] 移除或合并临时/重复 UI 区块

[!] 检查 1600x900 下主要工作流是否舒适：当前 Electron 离屏截图验证受环境 ERR_FAILED 限制，需 GUI 手工复核
[!] 检查 1920x1080 下信息密度是否合理：当前 Electron 离屏截图验证受环境 ERR_FAILED 限制，需 GUI 手工复核
[x] 运行 tsc
[x] 运行 npm build
```

验收标准：

```text
[x] 后续每个功能都有明确面板归属
[x] 主界面不再依赖新增窗口承载新功能
[x] 用户第一眼能区分输入、预览、处理、导出、验收
[!] 常见桌面分辨率下不遮挡、不挤压、不溢出：代码和构建已通过，仍需 GUI 手工复核
```

## 4. Phase 6C：序列质量验收与问题帧检测

目标：处理完成后，软件主动告诉用户这一批结果是否稳定，哪些帧需要检查。

需求：

```text
1. 统计输入帧、Raw 帧、Soft 帧数量。
2. 检查数量是否一致。
3. 统计每帧非透明面积。
4. 检测 alpha 面积突变。
5. 检测 Raw 到 Soft 面积异常收缩。
6. 输出疑似问题帧列表。
7. 在界面中显示质量摘要。
8. 支持点击问题帧跳转预览。
```

执行清单：

```text
[ ] 在 Electron main.ts 增加 PNG alpha 统计方法
[ ] 设计 QualityReport 数据结构
[ ] 批处理完成后生成质量报告
[ ] 记录 totalFrames / rawFrames / softFrames
[ ] 记录每帧 alphaCoverage
[ ] 计算相邻帧波动
[ ] 设置疑似问题阈值
[ ] 标记 frameIndex、fileName、reason
[ ] 前端增加“质量验收”面板
[ ] 显示总帧数、疑似问题帧数、稳定性判断
[ ] 支持点击问题帧切换当前预览帧
[ ] 技术细节放入详情，不堆主界面
[ ] 用 E:\cuts\test 至少 3 组样本验证
[ ] 运行 tsc
[ ] 运行 npm build
```

验收标准：

```text
[ ] 数量不一致能明确提示
[ ] 明显闪烁样本能标出疑似问题帧
[ ] 正常样本不会大量误报
[ ] 用户能从问题列表跳到对应帧
[ ] 不影响现有批处理和导出链路
```

## 6. Phase 6E：模型与预设优化验证

目标：真正尝试提升核心效果，而不是只提示用户避开难素材。

需求：

```text
1. 验证当前 isnet-general-use 是否仍是最佳默认方案。
2. 对低对比、毛发、半透明样本做有限模型/参数对比。
3. 判断是否需要引入新模型或高级模式。
4. 将 C / F / I 从“强度差异”逐步转为“用途预设”。
```

执行清单：

```text
[ ] 整理当前 rembg 支持模型清单
[ ] 选 3-5 个代表样本：低对比、毛发、半透明、快速运动、普通背景
[ ] 不改正式链路，先用脚本离线跑对比
[ ] 记录 Raw 质量变化
[ ] 记录 Soft 修边变化
[ ] 判断是否有明显优于当前默认模型的方案
[ ] 如果有，设计“高级模型选择”方案
[ ] 如果没有，记录模型边界，不盲目接入
[ ] 重新评估 C / F / I 参数命名和用途
[ ] 提出“干净收边 / 细节保留 / 强力去脏边”预设方案
```

验收标准：

```text
[ ] 有明确模型对比结论
[ ] 不因为试验破坏当前稳定链路
[ ] 至少确定一个可落地的预设优化方向
[ ] 半透明能力边界有技术判断，不再停留在主观描述
```
