# 首批内测反馈与后续迭代计划

整理日期：2026-09-09

## 反馈来源与边界

依据产品负责人提供的用户测试汇总整理。尚无逐人测试记录、人数统计、原始问题素材和耗时数据；本文不把定性反馈转成量化结论。

## 本轮结论

- 上手有门槛，但指导一次后用户都能完成操作。下一轮应验证用户能否不依赖指导独立完成首次任务。
- 序列图播放与查看是用户反馈中使用最多的功能，应优先强化其独立使用流程。
- 特效去背景和复杂背景处理未达到用户预期。作为完整去背景产品推向市场前，需要明确支持范围并通过真实素材验收。
- 当前可继续定向内测；暂不扩大完整去背景产品的市场宣传。

## 格式支持核对

反馈原文为“现在只能针对 MP3 格式切序列图”，可能指 MP4，具体使用素材待确认。

反馈整理时，代码中的视频选择和扩展名检查包含 MP4、MOV、WEBM、MKV，未包含 GIF。PNG 序列可直接导入播放。2026-09-09 本轮开发已新增 GIF 入口与原始拆帧，验证结果见本轮验证记录。

## 已确认阶段：序列查看功能增强

唯一主目标：在已有直接打开播放、背景切换、速度调整、放大和拖动基础上，补齐 GIF 拆帧、放大检查和部分帧循环。直接打开序列即可播放是现有基线，不是待开发目标。

1. 选择视频支持 GIF；选中后 FPS 和时长置灰，直接拆成原始 PNG 序列，不重采样或截断。
2. 放大窗口内滚轮只缩放图像，阻止底层界面滚动。
3. 放大窗口增加默认不勾选的“使用主预览背景”。勾选后可使用主预览的背景选项；取消后恢复原有效果，保留缩放、位置和播放状态。
4. 增加起始帧和结束帧，支持指定区间连续循环；取消区间循环后恢复全帧播放，不修改原始素材。

验收：GIF 帧序、透明度、局部帧合成与原始时长正确；普通视频切帧不回归；放大背景可选且默认效果不变；滚轮不带动页面；范围循环、单帧范围和换素材重置正确。开发验证见 [序列预览优化验证记录](序列预览优化验证记录.md)，后续仍需真实用户和绿色包验收。

## 后续阶段：复杂背景与特效可行性验证

唯一主目标：明确哪些素材能达到可交付质量，以及所需技术路线。

- 收集经授权的问题素材，分别建立复杂背景主体、纯色背景特效、发光/半透明特效样本组。
- 每组记录用户期望保留的区域、透明度和允许的瑕疵；不能只用“背景扣掉了”作为成功标准。
- 将主体分割、纯色去底和半透明特效恢复作为不同候选路线验证，不预设更换一个模型即可全部解决。
- 对比主体完整性、光效保留、边缘残色、帧间闪烁、速度、内存、离线运行和包体成本。
- 在黑白背景和实际目标背景上复核。达到预先约定标准后才接入正式流程；未达标则继续记录限制。

## 发布顺序与门槛

先完成播放与上手改进，再根据素材验证结果确定去背景优化范围。每次只实现一个明确目标，发布版本号在实际变更范围确定后再决定。

序列查看功能的使用价值可以独立验证，但不能据此宣布完整去背景产品达标。扩大市场发布前，必须完成核心素材质量验收、无需指导的上手验证和绿色包回归。

每阶段更新 ITERATION_BASELINE.md；代码修改运行 tsc 和 npm build，涉及打包或运行时则追加 Python import、完整流程和干净电脑验证。

## 2026-09-12 更新：本轮已验收

GIF / WebP 原始拆帧、透明度保留、区间循环、放大预览与背景下拉顶栏，以及固定一键打包已完成，用户确认对应 ZIP 验收通过。详见 [发布验收记录](发布验收记录-20260912.md)。前文待办保留为历史背景，不再重复安排这些已完成能力。

## 下一阶段推荐：缩略图时间轴与可视化选段

状态：规划草案，未获开发授权，未开始实现。

唯一主目标：让用户通过画面找到关键帧并选择循环片段，减少反复逐帧翻找和输入帧号。依据是既有用户反馈中播放/查看使用最多，而不是将“打开即可播放”再次当作新目标。

1. 增加可折叠缩略图条，显示帧号、当前帧和选中区间；点击缩略图定位，播放时高亮当前帧。
2. 支持将当前帧设为区间起点或终点，与现有数字输入同步；保留数字输入，避免强迫用户只靠拖动选段。
3. 缩略图按可见区域懒加载，限制并发与内存，切换素材取消旧任务；只为时间轴服务，不扩展成素材库系统。

建议验收：使用 20 帧和 1,000 帧样本验证定位、范围含两端、单帧循环、换素材重置及源文件不变；920/1440 宽度无重叠；长序列不一次性解码全部缩略图，加载时播放与拖动不被阻塞。请 3–5 位真实用户不看口头演示完成“找关键帧并循环一段”，记录完成情况和困惑点。

阶段不做：全界面重构、会员/账号、云端、素材管理库、新抠图模型集成。

## 后续顺序建议

1. 查看工作流简化：依据时间轴实测，再整理导入、播放、导出入口及高级参数折叠；不先全面改版。
2. 纯色底半透明抠图验证：沿用已有独立复现成果，在新图片和短序列上检查主体保护、光效、残色、帧间闪烁及人工标记成本；通过后才提出小范围集成方案。
3. 复杂背景专项：单独建立授权素材和验收标准，不将纯色去底成功外推到任意复杂场景。

维护项：单独复现开发缓存权限提示与旧 IPC 监听异常，按实际影响安排窄范围修复；不将它们描述为已解决。下次候选包建议递增版本号（例如 `0.4.0-internal.2`），避免不同功能包长期共用一个版本；当前归档不改历史包名、版本或标签。
